4. The lifetime question
------------------------

Answered, in a new section 4.11, "Reference Captures of Temporaries".

You are right that the existing rules settle it, and your reasoning holds:
braced aggregate initialization does get full lifetime extension. The
full-expression exception in [class.temporary] 6 is narrower than it looks
-- it covers parenthesized expression-lists, new-initializers and reference
parameters, not braced init.

Answers to Yihan's three questions, verified on Clang 21 and GCC 16:

  (c) The temporary belongs to one closure object -- the one whose
      init-capture created it.
  (b) Yes, a copy that outlives the original dangles. Copies bind their own
      reference to the same object and extend nothing; the temporary dies
      with the original.
  (a) Returning is the sharp edge. The temporary does not survive the
      return. By guaranteed copy elision the closure object is the
      caller's, but the temporary was materialized in the callee's frame.

That last one is worth knowing about. A literal reading of the wording says
the opposite: the init-capture variable's lifetime ends with the closure
object's ([expr.prim.lambda.capture] 6), and the temporary persists for the
lifetime of the reference ([class.temporary] 6). If the closure is the
caller's, so is the temporary -- which no implementation does and none
could. It is reachable in C++26 and not introduced by us, so 4.11 notes it
for CWG and suggests a core issue rather than handling it here.

One more thing: GCC rejects [&x = g()] for a const-returning g outright,
though it accepts auto& x = g();. That contradicts the "as if it declares
auto init-capture ;" rule, so it looks like a bug. It also means the
existing spelling is barely exercised, which strengthens the case that this
is newly reachable rather than merely newly convenient. 4.11 says so.


5. Other changes to the sections you commented on
-------------------------------------------------

Checking your items turned into some restructuring of the same sections, so
these are worth knowing about before you next read the paper.

4.6 gained an Applicability subsection, which the two by-copy sections
already had and this one did not. It has content rather than just symmetry:
unlike the by-copy forms, a const& capture is never redundant, because [&x]
does not give a const view on a const lambda. The cells give the meaning of
x in the body rather than a desugared struct, since a reference capture need
not declare a member.

4.8 gained a 2x2 table. Six spellings were argued across three paragraphs
with two different rationales buried in them. const and mutable share a
column, because the obstacle depends only on whether the target is captured
by reference or by copy, not on which qualifier is written. This is the
section you said you would write about, so it may want reconciling with
whatever you had in mind.

4.9 gained a table of the existing rules, above the one comparing candidate
designs, so it is clear which existing form each design column corresponds
to. It includes a const T& row, which is where "a copy of a const view is
const" in 4.10 comes from. The section now also states its scope in the
opening rather than at the end, and the decision has its own subsection.

Building that table turned up a claim that was wrong in two places. Both 4.9
and 7.1 said a qualified simple-capture and the corresponding init-capture
deduce the same member type. For a reference to a function they do not: the
type rule settles that case before the qualified branches apply, so
[const fr] leaves T(&)() with the qualifier inert while [const y = fr]
decays to const T(*)(). Verified on Clang 21 and GCC 16. Both now note it.

7.5 gained the lifetime case, since 4.11 concludes the existing rules settle
it and that section is where "needed no wording" is catalogued.
